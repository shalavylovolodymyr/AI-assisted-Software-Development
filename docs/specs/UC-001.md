# UC-001 — Create and assess an issue

## Intent
Capture an accountable issue and a reproducible initial risk evaluation atomically.
## Actors
Fictional demo team member; selected actor is also reporter and assessor.
## Preconditions
Active project, known assignee, known actor, demo writes enabled.
## Inputs
Project UUID, title, description, category, priority, assignee UUID, optional
due date, strict integer likelihood/impact 1–5, nonblank rationale.
## Flow
1. Validate fields and referenced records.
2. Allocate UUID and unique human reference.
3. Calculate risk using pure scoring function.
4. Store OPEN issue, immutable assessment, creation and risk audit events in one transaction.
5. Return issue details/current risk with version 1.
## Alternative flows and errors
422 invalid fields/risk; 404 missing references; 409 archived project or uniqueness conflict.
Failure leaves no partial rows. No deletion or external notifications in scope.
## Postconditions and acceptance
Given valid references, creation returns 201, correct score/severity and persisted history.
Given invalid risk or references, no issue/assessment/audit is added.
Dashboard, issue list and matrix derive the new issue after refresh.
## Tests
Unit: risk boundaries, fake-UoW creation/rollback. Integration/API: atomic creation,
foreign keys, invalid payloads, not-found. E2E-001 creates through the actual form.
## Non-functional
UTC storage; explicit API contract; no ORM leakage; no framework imports in domain/application.
