# UC-002 — Plan and complete mitigation

## Intent
Assign actionable corrective work and retain completion evidence.
## Actors
Known demo user; owners update their actions; MANAGER/ADMIN may update any action.
## Preconditions
Issue OPEN or IN_PROGRESS for planning; current issue version supplied.
## Inputs
Issue UUID, title, description, owner UUID, due date. Update: action status and expected issue version.
## Flow
1. Lock issue, validate version, issue state and owner.
2. Add TODO action and audit event atomically; increment issue version.
3. Allow TODO → IN_PROGRESS/DONE/CANCELLED; IN_PROGRESS → TODO/DONE/CANCELLED.
4. DONE sets completion timestamp and adds completion audit event.
## Alternative flows and errors
404 missing records; 403 non-owner member; 409 stale version, terminal/same action
transition or planning on mitigated/resolved issue. DONE/CANCELLED are terminal.
Cancelled actions do not block mitigation; an all-cancelled plan cannot resolve.
## Postconditions and acceptance
Multiple actions persist after refresh. Completion is timestamped and auditable.
Failed mutations leave the issue version, action and history unchanged.
## Tests
Unit: transition matrix, owner checks, fake-UoW actions. Integration: rollback,
FK integrity, action completion and dashboard progress. E2E-003 runs the full workflow.
## Non-functional
Parent issue row lock serializes all aggregate writes; no lost action updates.
